Why Most Teams Over-Use Client Components

Priya Nandakumar · Oct 9, 2026 · 6 min read

When the App Router shipped, a lot of teams did the easy thing: slap 'use client' at the top of every file and move on. It works, but it quietly undoes most of the benefit of the new model.

The directive isn't free. Every file it touches — and everything that file imports — gets pulled into the client bundle, whether or not it actually needs to run in the browser.

"'use client' is an opt-in, not a default you reach for out of habit."

A good rule of thumb: start every new component as a Server Component. Only add the directive when the compiler actually complains, or when you reach for a hook, a handler, or a browser-only API.

In practice this means your page shells, your layout chrome, and your static display primitives almost never need it — it's the small, genuinely interactive leaves of the tree that do.
